# 怎样验证这套方案有没有用

本次磁盘案例验证了任务结果。经验库是否改善后续工作，需要另外做对照试用。

## 对照方式

选取同一组尚未用于编写经验的新任务，在相同模型版本、工具、权限、任务目标和初始环境下分别试用：

| 组别 | 提供的信息 |
| --- | --- |
| A | 当前任务与必要现场信息，不提供历史经验 |
| B | 当前任务、必要现场信息和完整历史记录 |
| C | 当前任务、必要现场信息和关键词经验库 |

不让前一组修改过的环境直接成为下一组的初始环境。出现随机性时使用多次独立尝试，保留每次结果，不只挑成功的一次。

启用评分时，固定起始 registry 与分数，各组使用独立副本；一次试验记录的成功或失败不能泄漏到下一组。长期累积计分的收益另做持续试用，和固定状态的对照结果分开报告。

## 记录指标

- 按相同外部验收标准计算任务成功率。
- 统计总输入量，包括索引、经验、额外检索、失败重试和验收调用。
- 统计总耗时和工具调用数；需要比较成本时使用实际账单或同一价格口径。
- 区分“有成功经验的任务”“没有匹配经验的任务”和“经验已不适用的任务”。

同时报告成功率与消耗。如果输入减少但任务失败变多，需要继续改进。还应记录经验生成和维护成本，长期比较时纳入总成本。

## 跨 AI 可读性

让没有原始聊天历史的另一个 AI，仅凭接入说明、索引和选中经验回答：何时适用、怎样执行、怎样验收、哪些结果尚未验证。能正确回答后，再在隔离测试环境中检查实际复用。

完成这一步前，使用“格式面向不同 AI”“尚待跨模型实测”等表述。不要写“任何 AI 都已经验证可用”。
