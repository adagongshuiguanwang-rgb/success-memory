# Success Memory · 关键词经验库

**用短词找到经验，用结果决定保留。**

把实际完成并验收的项目经验保存在文件中。AI 遇到相似任务时，通过“存档”“磁盘”等主题词找到最匹配的做法，读取必要内容，执行并验收。

这是 v0.2 方案草稿。它适用于开发、修复、设计、运营及其他能明确验收结果的工作，不绑定某个模型或工具。

## 核心流程

```text
任务 → 主题索引 → 适用项按分从高到低读取 → 执行与验收
                     ↓ 没有匹配项
                按现场情况完成任务
                     ↓ 验收成功
                提炼、合并、写入经验
```

上下文保留主题入口，经验正文和证据按需读取。成功加分，失败减分；失败方案不进入成功库，已被证明失效的经验退出调用。

## 怎样开始

1. 把这个目录放在 AI 可以读取的位置。
2. 参考 [AGENTS.example.md](AGENTS.example.md)，将入口位置写进所用 AI 工具的常驻说明。文件名是否自动加载，取决于工具配置。
3. 从 [memory/INDEX.md](memory/INDEX.md) 查主题，只读取适用的经验。
4. 完成任务并验收后，按[六字段模板](templates/experience.md)记录成功做法。

## 成功计数与失败减分

```text
净分 = 成功次数 − 失败次数
成功一次：成功次数 +1，净分 +1
失败一次：失败次数 +1，净分 −1
```

在同一主题中，核对 scope 后优先读取最高分的适用项。同分时，失败次数少的优先，再按 id 升序。净分可以为负；确认失效的条目设为 paused，不参与自动读取。

计数放在 [memory/registry.json](memory/registry.json)，正文仍保持六字段。每次任务最终验收使用全库唯一的 event_id，重复记录不加减分；仅读取、计划、取消和结果不明的尝试不计分。新经验至少有一次实际成功才入库。现有 DISK-001 为成功 1 次、失败 0 次、净分 1。

使用 Python 3 标准库工具，无须安装额外依赖：

```sh
python tools/memory.py rank --topic 磁盘
python tools/memory.py record DISK-001 --result success --event-id <唯一任务验收编号> --evidence <仓库内证据文件>
python tools/memory.py record DISK-001 --result failure --event-id <另一个唯一任务验收编号> --evidence <仓库内证据文件>
python tools/memory.py reindex
```

record 更新计数并重排 Markdown 索引；rank 只读，返回排序后的候选摘要。命令中的占位项需要替换，示例不代表又完成了一次成功或失败。手工改 registry 后需要 reindex。单次只运行一个写入者；如果计数已提交而索引生成中断，运行 reindex 恢复。

计分器记录已经验收的结果，不替使用者判断证据真伪；高分也不代表一定适合当前任务。

计分、去重和排序已通过[12 项功能测试](docs/scoring-check.md)。可在仓库根目录运行 `python -m unittest discover -s tests -v` 复查，测试仅写临时库。

没有文件访问能力的聊天工具，可以由用户提供索引与选中经验；它无法自行读取电脑上的经验库。

## 一条经验需要什么

| 字段 | 内容 |
| --- | --- |
| id | 稳定编号 |
| scope | 主题、项目、环境和使用前提 |
| problem | 已解决的问题 |
| action | 最短可执行步骤及必要文件位置 |
| acceptance | 验收方法、实际结果、日期和未覆盖范围 |
| evidence | 可复查的证据位置及其公开程度 |

使用 UTF-8 Markdown、固定字段名和明确动作。证据、代码和大文件使用相对链接，经验不依赖原聊天才能读懂。

## 这次已有的实测

[DISK-001](memory/disk/DISK-001.md) 来自一次真实的 Windows 缓存清理：删除 4,572 个旧缓存和临时文件，操作期间空闲空间增加约 4.00 GiB。公开包提供[脱敏结果摘要](examples/disk/result.json)和[对应脚本](examples/disk/cleanup-old-caches.ps1)。

这只证明一次任务的清理结果；**尚未证明这套经验管理方式能降低多少 token、成本或失败率**。原始本机清单未公开，脱敏摘要无法替代独立复现。

## 使用边界

- 主题词用于定位，项目和环境用于匹配；同名问题可能需要不同方法。
- 短词能生效，需要固定入口和可访问的经验文件。系统自动压缩的最终内容由运行工具管理。
- 原始资料可以留在资料目录；经过验收的经验才进入可调用成功库。
- “重写故障接口”可以是一条特定条件下的成功方法；方法由经验适用条件与当前任务决定。
- 正在进行的任务用独立状态文件恢复，完成后退出活动状态；成功库只保留已完成经验。

完整规则见 [PROTOCOL.md](PROTOCOL.md)，验证思路见[试用与评估](docs/evaluation.md)。已完成一次[独立会话可读性检查](docs/readability-check.md)，跨模型效果仍待实测。欢迎用实际项目检验这个方案。
